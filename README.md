# Python Junior Mock

Отдельная программа для Windows: голосовое тренировочное интервью на русском для Junior Python Developer (ориентир — Яндекс). **Неофициальная симуляция**, а не собеседование от Яндекса.

Виртуальный интервьюер задаёт 5, 8 или 10 основных вопросов, слушает ответы, может уточнять и после завершения выдаёт оценку по расшифровке. На экране портрет собеседника. Голосовой движок — GPT-Live-1, оценка — GPT-6 Luna через OpenAI API.

## Как скачать установщик

1. Откройте вкладку **Actions → Build Windows installer** и дождитесь зелёной сборки.
2. Откройте сборку → **Artifacts → Python-Junior-Mock-Windows** и скачайте ZIP.
3. Распакуйте ZIP и запустите `Python-Junior-Mock-Setup-1.3.5.exe`.

GitHub → Code → Download ZIP скачивает **исходники**, а не установщик. Windows может предупредить о неподписанном издателе.

## Первый запуск

Разрешите доступ к микрофону в Windows. Нужен API-ключ проекта [OpenAI Platform](https://platform.openai.com/api-keys) с доступом к `gpt-live-1` и `gpt-6-luna`. Вставьте ключ в программе, выберите количество вопросов и нажмите «Начать интервью». Лучше использовать наушники.

Ключ используется в памяти процесса и, **если включено «Запомнить ключ на этом ПК»**, сохраняется локально в зашифрованном виде через Windows DPAPI (`electron.safeStorage`). Аудио/расшифровка передаются OpenAI для голосового диалога и оценки. Это отдельные платные API-запросы; подписка ChatGPT Plus не покрывает их.

## Для разработчика

```sh
npm install --no-audit --no-fund
npm test
npm start
npm run dist
```

Electron и electron-builder собирают Windows NSIS-установщик через GitHub Actions. Для сборки на Windows понадобится Node.js 22+.

## Ограничения

- Тесты без API-ключа проверяют локальную логику, но не доказывают работу живого голосового диалога.
- Количество вопросов регулируется инструкцией модели; строгое соответствие 5/8/10 в живой речи не гарантируется.
- Портрет статический; не видеоаватар.
- Вопросы не заявлены как подлинные вопросы конкретного рекрутера Яндекса.
- Интервью и результаты сохраняются локально в папку отчётов; оценки зависят от точности расшифровки. Встроенного экрана истории пока нет.

Документация API: [GPT-Live WebRTC](https://developers.openai.com/api/docs/guides/voice-webrtc?api=live) · [Live sessions](https://developers.openai.com/api/docs/guides/live-conversations) · [Delegation](https://developers.openai.com/api/docs/guides/live-delegation).

## Автоматический архив интервью — v1.3.0 (2026-11-06)

- При первом запуске по умолчанию используется папка **Документы → Python Junior Mock → Интервью**. В блоке «Автоматическое сохранение интервью» можно выбрать любую другую папку и открыть её.
- После успешной оценки автоматически создаётся **PDF** со всей расшифровкой, датой, длительностью разговора, оценкой и рекомендациями. Длительность фиксируется **до** запроса на оценку. Имя файла включает дату и уникальный ID.
- По умолчанию рядом сохраняется **JSON** с теми же данными для последующего анализа; галочку «Дополнительно сохранять JSON» можно выключить.
- При поступлении фрагментов речи приложение последовательно сохраняет актуальную расшифровку в `app.getPath('userData')/interview-drafts` без прежней фиксированной задержки 800 мс. При экстренном выключении питания последний ещё не записанный фрагмент всё равно может потеряться. Локальные записи хранятся также после экспорта для истории и повторного сохранения.
- Итоговая оценка сначала записывается в локальную запись интервью (независимо от настройки JSON), и лишь затем создаются PDF и дополнительный JSON. При сбое PDF появляется кнопка **«Повторить сохранение PDF»** без повторного платного запроса к GPT-6 Luna.
- **Аудиозаписи не сохраняются**. Отчёты и черновики хранятся локально и содержат текст разговора; не выбирайте общедоступную папку, если ответы личные.
- Для прерванных интервью и сбоев оценки доступна панель **«История и восстановление»**. Она показывает последние 20 локальных записей (в том числе без оценки) и позволяет сохранить их в PDF, а при включённой опции и JSON, в выбранную папку без обращения к API. Раздел истории открывается в настройке новой тренировки.


### Обновление 1.3.1 (2026-11-07) — восстановление результатов

- Прерванные интервью доступны в истории и экспортируются с пометкой **«Без оценки»**. После сбоя достаточно открыть приложение и нажать «Сохранить PDF».
- Локальная история и восстановление хранятся **в служебной папке профиля Windows в незашифрованных JSON-файлах**, даже если дополнительный JSON при экспорте отключён. Это необходимо для восстановления оценки и расшифровки. Храните профиль Windows под паролем; не копируйте служебные файлы в общие папки.
- Автоматическая запись текста начинается при получении фрагментов распознавания; операции объединяются при параллельной записи на диск. Она уменьшает, но не исключает потерю последнего фрагмента при мгновенной аварии.
- Windows CI выполняет отдельную проверку создания **реального PDF в Electron** (с оценкой и без оценки), в дополнение к модульным тестам. Проверка структуры PDF не заменяет ручной визуальный просмотр на целевом ПК.

## Обработка двух говорящих и контроль основных вопросов — v1.3.3 (2026-11-07)

- GPT-Live присылает `session.input_transcript.delta` и `session.output_transcript.delta` с временными интервалами, **но без признака конца реплики**. Программа теперь отдельно собирает кандидата и интервьюера; изменение собеседника не превращает остаток ответа кандидата в новую реплику автоматически. Фрагменты сортируются по меткам времени. Дубликаты `event_id` не удваивают текст.
- Границы реплик при долгих паузах **приблизительные**: API не позволяет абсолютно точно восстановить каждую человеческую реплику только по этим событиям. Данные с различными ролями не смешиваются.
- Каждый **новый основной вопрос** интервьюер должен начинать короткой фразой `Вопрос N:`. Только последовательные подтверждённые номера увеличивают счётчик. Уточняющие вопросы без номера в него не попадают. Счётчик показывается в интервью.
- На последнем основном вопросе клиент отправляет дополнительное указание завершить интервью после ответа. Если появляется явный маркер `Вопрос N` с номером **больше выбранного лимита**, приложение завершает голосовую сессию и переходит к оценке.
- **Ограничение:** модель может проигнорировать требование нумерации, а текст/звук может поступить с задержкой. Поэтому это защита от наблюдаемого превышения и более точный учёт, **не математическая гарантия** ровно N вопросов. При отсутствии надёжных маркеров приложение показывает план, не выдавая неизвестное количество за подтверждённое.
- В итоговую оценку передаётся число **подтверждённых нумерованных** основных вопросов, чтобы не считать уточнения основными. Если маркировка пропущена, значение может быть меньше фактического количества.

Ссылка для следующей отдельной задачи с иконкой, **ещё не заменённой на точный исходник**: `QuickCue/knowledge/docs/design/logos/graphite-q-wave-source.png`. Подключение к приватному репозиторию возвращает для этого большого файла только SHA и метаданные, без байтов PNG, поэтому утверждать, что этот конкретный исходник установлен в Windows, пока нельзя. Текущий значок Windows остаётся построенным из `AppIcon-1024.png`, пока точный файл не будет доступен для копирования.

## Надёжность GPT-Live и контроль длительности — v1.3.5 (2026-11-07)

- Голосовая сессия автоматически ограничивается **30 минутами от начала HTTP-запроса её создания**, включая задержку подключения. Пять минут до лимита появляется предупреждение, в интервью виден обратный отсчёт. Лимит фиксированный, чтобы не перегружать настройки.
- **Ограничение действует в главном процессе Electron**, а не только в интерфейсе: по дедлайну приложение отправляет `POST /v1/live/sessions/{session_id}/hangup` с ключом на стороне главного процесса, а интерфейсу — сигнал завершить разговор и попытаться оценить ответы. При закрытии Windows-приложения отправляется такой же запрос (с ограниченным ожиданием).
- При ручном завершении, отмене подключения и возврате на старт запрос на завершение сессии отправляется при необходимости. Одновременно не разрешается создавать несколько платных Live-сессий.
- **Это защита от случайного перерасхода времени, а не точный финансовый лимит.** Расходы делегированной GPT-6 Luna/Responses и оценки начисляются отдельно. Ошибки сети, аварийное завершение ОС и сон устройства не позволяют абсолютно гарантировать момент остановки на удалённом сервере.
- Результаты `session.usage.updated` учитываются **накопительно** по `usage.seconds` (не суммируются). Счётчик оставшегося времени основан на серверной точке дедлайна приложения, а не на ненадёжном таймере отдельных кадров интерфейса.
- Режим **«Подключение»** не показывает «Интервью идёт» до выполнения трёх условий: пришло `session.started`, применён SDP-ответ и открыт WebRTC DataChannel. Если за 20 секунд после HTTP-ответа подтверждение не пришло, приложение завершает сессию и позволяет повторить попытку. Есть кнопка «Отменить подключение».
- Чтобы **первый вопрос звучал надёжнее**, в запросе `session.input` добавлен один `developer`-текст на русском с просьбой начать разговор. После `session.started` и готовности транспорта тот же текст однократно отправляется через `session.commentary.append`, как рекомендует OpenAI. `session.commentary.appended` не считается доказательством того, что голос прозвучал.
- Если спустя 12 секунд нет фрагментов речи интервьюера, появляется **ручная** кнопка «Повторить первый вопрос». Допускается только один повтор — бесконтрольные автоматические запросы исключены.
- Если лимит достигнут, приложение пытается сохранить имеющуюся расшифровку и получить оценку. Если ответов недостаточно для оценки, черновик остаётся доступен в «Истории и восстановлении».
- Автотесты охватывают многопоточные порядки событий готовности, таймаут, повторные события, завершение сессии по лимиту, отмену, накопительные данные usage, инициализацию приветствия и передачу ID в команду серверного завершения. Проверка реального микрофона и OpenAI API не входит в бесплатный CI.
