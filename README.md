# QuickCue · Python Junior Mock (Windows)

Голосовое тренировочное интервью на русском языке для Python Backend / Junior. Это **неофициальная** симуляция, а не собеседование от Яндекса.

- **GPT-Live-1** — разговор через микрофон и WebRTC.
- **GPT-6 Luna** — техническая помощь интервьюеру и отдельная оценка после интервью.
- 5, 8 или 10 основных вопросов, краткие уточнения, оценка 1–10.
- Автоматический PDF и необязательный JSON; локальная история и восстановление прерванных тренировок.
- Светлая и тёмная темы QuickCue, рисунок графитовой Q с пятью полосами волны.

## Установка

1. Открой [GitHub Actions](https://github.com/voityvaity/new/actions/workflows/windows.yml) и выбери последнюю **успешную** сборку ветки `main`.
2. Скачай артефакт `Python-Junior-Mock-Windows` и распакуй ZIP.
3. Запусти `Python-Junior-Mock-Setup-1.3.8.exe`. Неподписанный установщик может вызвать предупреждение Windows.

Для первого запуска нужен микрофон и API-ключ с доступом к моделям `gpt-live-1` и `gpt-6-luna`. API оплачивается отдельно; подписка ChatGPT не включает эти расходы.

## Работа с интервью

Введите API-ключ, выберите количество вопросов и нажмите «Начать интервью». Вопросы считаются по явным меткам «Вопрос N:», уточнения не считаются. Поскольку границы реплик распознаются приблизительно, счётчик может отставать: он не гарантирует ровно заданное число вопросов. По окончании нажмите «Завершить и оценить».

Запись расшифровки создаётся локально по ходу речи. После успешной оценки PDF автоматически сохраняется в папке `Документы/Python Junior Mock/Интервью` либо в выбранном каталоге; необязательный JSON можно выключить. Если приложение закроется до оценки, доступную расшифровку можно восстановить в разделе «История и восстановление». Аудиозаписи на диск не сохраняются.

**Длинные ответы не обрезаются молча.** В архиве сохраняется полный текст в пределах явного защитного ограничения (500 000 символов на интервью). Автоматическая отправка на оценку ограничена 250 000 символами, чтобы не получить непредсказуемо дорогой API-запрос; при превышении приложение сообщает об этом, а локальный текст остаётся.

## Защита платной сессии

- Приложение пытается завершить сессию через **30 минут от начала запроса создания**, включая ожидание подключения. За 5 минут появляется предупреждение. При аварии или зависании гарантировать удалённое завершение нельзя.
- Для WebRTC приложение отправляет `session.close` по DataChannel и ожидает `session.closed` с причиной и итоговым использованием. **Только `session.closed` подтверждает завершение.**
- Если терминальное событие не пришло, сессия остаётся в состоянии **«завершение не подтверждено»**. Новое платное интервью блокируется, пока пользователь явно не примет риск. Статус записывается в локальный файл без API-ключа и сохраняется между запусками.
- Серверный `/live/sessions/{id}/hangup` используется лишь как резервная попытка; этот endpoint документирован для SIP и **не является подтверждением закрытия WebRTC**.
- При закрытии окна приложение пытается дождаться финального события и сохранить черновик. Падение процесса, отключение сети/питания или недоступность OpenAI не позволяют абсолютно гарантировать удалённое завершение. Проверяй [Usage](https://platform.openai.com/usage) при сомнениях.
- Лимит — **по времени**, не по сумме денег: отдельные запросы GPT-6 Luna оплачиваются независимо.

## Приватность

API-ключ используется в памяти. При включении «Запомнить ключ» он сохраняется через Windows DPAPI / Electron `safeStorage`, без открытого ключа на диске. Текст разговоров передаётся OpenAI и сохраняется в локальной папке профиля Windows **без отдельного шифрования** для восстановления после сбоя. Не используй общедоступную папку для личных ответов.

## Для разработчика

Требуется Windows, Node.js 22+, микрофон для живых тестов.

```sh
npm install --no-audit --no-fund
npm test
npm run test:pdf
npm run test:ui
npm start
npm run dist
```

CI запускает тесты, проверяет настоящий PDF средствами Electron, светлую и тёмную тему, иконку, затем собирает NSIS-установщик. **39 и более прошедших тестов не являются доказательством работы с настоящим API.** Живой WebRTC-тест требует действующего платного ключа, микрофона и проверки первого вопроса, обрывов сети и конечного события `session.closed`.

Известные ограничения: распознавание может неточно разделять человеческие реплики; модель может игнорировать нумерацию; статический портрет — не видеоаватар. Иконка Windows сформирована из **векторной трассировки** присланного рисунка, а не побайтовой копии исходного PNG.

## Исправления 1.3.7 (7 ноября 2026)

- Сокращён риск потери оплаченной оценки при закрытии окна: программа дожидается завершения запроса к Responses и сохранения результата (не более 105 секунд). Успешно сохранённая оценка повторно используется без нового API-запроса.
- Повторная оценка после сетевого таймаута требует явного согласия: прежний запрос мог оказаться оплаченным, даже если клиент не получил ответ.
- Очистка сохранённого ключа и изменение разрешения сохранять его имеют приоритет перед запоздалым ответом создания голосовой сессии.
- При потере WebRTC-соединения выполняется не более одной дополнительной попытки серверного завершения. **HTTP hangup не считается подтверждением закрытия WebRTC**, пока не получено `session.closed`. Если подтверждения нет, статус остаётся неопределённым.
- Короткие ответы вроде «Не знаю» оцениваются как действительные ответы; без распознанной речи кандидата оценка по-прежнему невозможна.
- Фрагменты кандидата по разные стороны реплики интервьюера больше не объединяются безусловно. Для надёжной диаризации нужен живой голосовой тест.
- Счётчик распознаёт нумерованные вопросы после разговорных вступлений; уточнения без номера не включаются.
- Расшифровка сохраняется с объединением частых обновлений (не более примерно 5 записей в секунду в обычном потоке), с принудительным сохранением при завершении.
- На экране показаны **последние 30 реплик**, а полный текст остаётся в локальной истории и экспортируемом PDF/JSON.

Ограничения: 30-минутный срок не является финансовым лимитом; удалённое завершение не гарантируется при отказах сети или ОС; таймаут Responses не доказывает, что запрос не был оплачен; графитовая иконка Windows является трассировкой предоставленного изображения. После автоматических тестов требуется одно живое интервью с проверкой микрофона, звука, оценивания и сохранения отчёта.

## Доработка 1.3.8 — чистый интерфейс и надёжность (7 ноября 2026)

- До отправки платного запроса приложение обязано создать локальный черновик и сохранить на диск маркер `creating`; после успешного ответа сохраняет `active` вместе с ID. При перезапуске из `creating/active/closing` восстанавливается `unconfirmed`. **Невозможность сохранить черновик блокирует платное подключение.**
- При подтверждённом отказе HTTP создания пустой черновик удаляется; при неизвестном сетевом исходе сохраняется предупреждение. Сведения об API-ключе в журнал не записываются.
- Счётчик вопросов остаётся ориентировочным. Распознанные метки больше **никогда не вызывают автоматического обрыва** беседы: окончание управляется пользователем либо лимитом времени. Убрана обманчивая подпись «Завершить после ответа».
- Первый экран показывает только название, тип интервью, API-ключ, число вопросов и главное действие. История и экспорт PDF/JSON сохранены в свёрнутом разделе «Отчёты и история». Удалены повторяющиеся описания, не относящиеся к действию.
- Расшифровка не прокручивается вниз, пока человек читает предыдущие записи. Вывод ошибок сохранения настроек больше не скрывается.
- Добавлены регрессионные проверки предоплачиваемого порядка операций, аварийного восстановления и положения кнопки «Начать интервью» в реальной области окна Electron.

**Остаётся без проверки:** качество распознавания двух говорящих, реальное завершение WebRTC при отключении сети/зависшем renderer, воспроизведение первого вопроса, реальный платный запрос итоговой оценки. Для этого требуется короткий ручной Windows-тест с API-ключом. Удалённое закрытие не гарантируется одним лишь локальным таймером.
